# 05 · 开发与交接手册

## 1. 三十秒了解项目

法院内网离线运行的刑事执行文书生成工具。输入判决书（生产用 PDF，开发用人工提取的 TXT），用**规则**抽取 A/B/C/D 四组字段，填入执行文书模板，规范命名归档。**运行端不部署任何模型。**

技术栈：Python 3.9+ / PyMuPDF / python-docx + docxtpl / SQLite / Tkinter / PyInstaller。

## 3. 立刻能跑的命令

```bash
python -m pip install -e ".[dev]"      # 首次
python -m pytest -q                     # 单元测试
python -m cedas clean "examples/S000__京0105刑初123号.txt"      # 看清洗结果
python -m cedas extract "examples/S000__京0105刑初123号.txt"    # 看抽取结果（JSON）
python -m cedas calc "有期徒刑三年六个月"                       # 刑期解析
python -m cedas doctor                  # 自检：路径 / 依赖 / 可写性
python -m cedas doctor --json           # 同上，机器可读
python -m cedas                         # 启动 GUI 骨架
python tools/make_truth_template.py     # 重新生成真值填写表
```

打包（需要**完整安装的 Python**，含 tcl/tk）：

```bash
pip install -r requirements-build.txt
python tools/build_offline.py --check-only   # 只查环境，20 秒
python tools/build_offline.py                # 打包 + 冒烟 + 出 zip
```

注意：打包会用 PyInstaller 自身的 Python 解释器，而不是 `python -m cedas` 用的那个。
若开发机是精简版 Python（无 tkinter），打包会直接被前置检查拦下。

## 4. 下一个动作（按优先级）

1. **拿到 20 份样本 TXT + 真值表**（当前阻塞项，等业务方提供）。
2. **在样本上跑 `cedas clean`，人工核对段落划分**——这是所有后续工作的地基，清洗错了后面全错。
3. **补首部锚点规则**：出生日期 → 身份证号 → 住址 → 强制措施。一条一提交，附 golden case。
4. **实现主文锚点与多被告人切分**（`一、二、三、` + `被告人X犯…罪` 双锚定）。
5. **在真 PDF 上验证 `pdf_reader`**，确认页码恢复且清洗结论与 TXT 通道一致。
6. **模板映射 + 占位符校验器**，端到端生成第一份执行通知书。
7. **在目标机（4GB / 旧 CPU）实机跑一次离线包**，记录冷启动、单份耗时、内存峰值。

## 5. 七条不能碰的红线

1. **不得在运行端引入任何模型**（ADR-001、ADR-008）。
2. **不得为 TXT 单独写清洗逻辑**（ADR-005）。两条通道必须共用 `cleaner.clean()`。
3. **不得硬编码样本特征**——具体案号、具体日期、具体姓名不得出现在正则里。
4. **不得把敏感数据提交进仓库**（见 `SECURITY.md`）。提交前必看 `git status`。
5. **不得静默降级**——规则版本不匹配、占位符未解析，一律报错，不许猜。
6. **不得让 `calc` 依赖 `ingest`**，也不许 `domain` 依赖第三方库（见 `02-系统架构.md` §1）。
7. **不得把可写数据写到 `BUNDLE_DIR`**（`_MEIPASS` / `_internal`）。打包后该目录退出即可能被删除，
   台账与生成文书会静默丢失。一切写入走 `APP_HOME`（ADR-011）。

## 6. 已知的坑（踩过的，别重踩）

| 坑 | 现象 | 处置 |
|---|---|---|
| 届满日差一天 | 4 年刑期算成 2027-01-01 | 必须 `− 1 日`，见 ADR-006；月末情形另有约定待确认 |
| 全角转半角误伤中文标点 | `，` 变成 `,`，断句逻辑失效 | 只转数字与拉丁字母，不转中文标点，也不做整体 NFKC |
| 案号正则漏刑终案 | 二审判决抽不到案号 | 已放宽，覆盖 初/终/再/更/抗 |
| 页眉页脚删掉正文首行 | 两页短文书丢了开头 | 位置判据必须配「跨页重复率」，单页唯一长行不删 |
| TXT 上通过、PDF 上失败 | 命中率虚高 | 见 §7 风险 |
| **打包后数据丢失** | 台账与生成文书退出即消失 | `_MEIPASS` 是临时目录。资源读 `BUNDLE_DIR`，数据写 `APP_HOME`（ADR-011） |
| **精简版 Python 打出的 exe 无界面** | 双击无反应，打包阶段毫无报错 | 构建机必须装 python.org 完整版并勾 tcl/tk；`build_offline.py` 已前置拦截 |
| **PyInstaller 产物输出恒为 GBK** | 设了 `PYTHONUTF8` / `PYTHONIOENCODING` 也无效，管道里中文成乱码 | bootloader 会重置 stdio。脚本判定只认 JSON 里的布尔与数值字段，不比对中文；解码按 utf-8 → gbk → mbcs 依次尝试 |
| **PyMuPDF 2.x 拖入 onnxruntime** | 包体积莫名涨数百 MB | 锁定 `pymupdf<2`，spec 显式 `excludes` `pymupdf4llm` / `pymupdf_layout` / `onnxruntime` |
| **构建因批量删除被拦而失败** | `--clean` 一次删上千文件被环境策略终止 | 构建脚本改为「移开旧产物」而非删除，同时也保留了上一版便于比对体积 |
| **交付 zip 无版本目录** | 解压后上千文件铺在桌面，用户找不到 exe | zip 内固定带一层 `CEDAS-<version>-win64/` |

## 7. 最大的未解风险

**TXT 通道缺少页码、字号、坐标三项信息，导致页眉页脚的位置判据、标题的字号判据在开发期无法验证。** 这意味着清洗层可能在开发样本上表现良好，却在真实 PDF 上失效。

处置：把「在 ≥10 份真实 PDF 上回归通过」设为阶段 2 的**退出门槛**，不满足不得进入模板映射。详见 `02-系统架构.md` §6。

## 8. 过程记录怎么用

`docs/journal/` 按日期记录每次工作会话：做了什么、为什么这么做、遇到的坑、留下的待办。**追加式，不修改历史条目。**

新接手时，按时间倒序读最近 3 篇即可掌握近期上下文；需要追溯某个决策的由来时，结合 `03-决策记录-ADR.md` 交叉查。
