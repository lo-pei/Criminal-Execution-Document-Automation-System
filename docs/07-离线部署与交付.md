# 07 · 离线部署与交付

> 适用对象：负责把系统送进法院内网的实施人员。
> 前置阅读：`02-系统架构`（分层）、`03-决策记录-ADR`（ADR-010 / ADR-011）。

---

## 1. 结论先行

**目标机不需要安装任何东西。**

这不是「把依赖打进安装包」的说法，而是字面意义：exe 内已包含 Python 解释器、Tcl/Tk 运行时、
PyMuPDF、python-docx、docxtpl、lxml 与 Jinja2。目标机没有 Python、没有 pip、没有 VC++ 运行库、
没有 .NET 更新，双击 `CEDAS.exe` 即可运行。

所以「内网无法下载基础环境」不构成障碍，只影响一件事：**构建必须在有网的机器上完成**。

```
       构建机（可联网）                    U 盘 / 光盘 / 内网文件中转
  ┌──────────────────────────┐          ┌──────────────┐
  │ 完整 CPython + 依赖       │  zip     │  CEDAS-*.zip │
  │ PyInstaller → onedir     │ ───────► │  SHA256SUMS  │
  │ 冒烟测试通过后产出 zip     │          └──────┬───────┘
  └──────────────────────────┘                 │
                                               ▼
                                 目标机（完全离线）
                             解压 → 双击 CEDAS.exe → 完成
```

## 2. 构建机准备

### 2.1 硬性要求

| 项 | 要求 | 不满足的后果 |
|---|---|---|
| 操作系统 | Windows 64 位 | PyInstaller 不支持交叉编译，Linux 构建的产物在 Windows 上不可用 |
| Python | **python.org 官方安装包 `3.8.10`**（默认配方，覆盖 Win7+Win10） | 版本不符会被构建闸门直接拒绝，见 2.4 |
| 解释器位数 | 64 位 | 32 位进程可用内存上限 2GB，与目标机低内存叠加后极易 OOM |
| 磁盘 | 预留 2GB | 打包中间产物约 300MB + 产物 150MB |

### 2.2 必须使用「完整安装」的 Python

**精简版 / 嵌入式（embeddable）Python 不含 tcl/tk，打出的 exe 双击后没有任何界面，
且打包过程完全不报错。** 这是本项目实测踩到的第一个坑：构建机自带的精简 Python
`import tkinter` 直接 `ModuleNotFoundError`，而 `pyinstaller` 对此一路放行。

`tools/build_offline.py` 已把这项检查放在最前面，缺 tkinter 会直接终止构建并给出处理办法。

自查方法：

```bat
python -c "import tkinter; print(tkinter.TkVersion)"     :: 应输出 8.6
```

安装 python.org 官方包时，务必勾选 `tcl/tk and IDLE`。

### 2.3 建议用干净虚拟环境

构建机上装了什么，PyInstaller 就可能顺着 import 链拉什么。典型污染源是 PyMuPDF 2.x 的周边包
（`pymupdf4llm`、`pymupdf_layout`，连带 `onnxruntime`，单独就有数百 MB）。
`packaging/cedas.spec` 已逐个排除，但干净环境能省掉一半打包时间和全部排查成本。

```bat
python -m venv .venv-build
.venv-build\Scripts\activate
pip install -r requirements-build-win7.txt
```

依赖清单固定了版本，避免「上个月能打、这个月打出来不一样」。

### 2.4 两套构建配方，产出一份包

因为目标机含 **Windows 7**，解释器只能停在 **Python 3.8.10**——CPython 3.9 起不再支持 Win7。
所以默认配方是「用 3.8 打一份包，同时覆盖 Win7 与 Win10」。

| 配方 | 解释器 | 何时用 | 产物名 |
|---|---|---|---|
| `requirements-build-win7.txt` | Python **3.8.10** | **默认**。还有 Win7 机器时 | `CEDAS-<ver>-win7-win64.zip` |
| `requirements-build-win10.txt` | Python 3.11 / 3.12 | Win7 机器全部退役后 | `CEDAS-<ver>-win10-win64.zip` |

两份配方**功能完全一致**，代码不需要改动，差别只在解释器与依赖版本。切换时重建虚拟环境并删掉 `dist/` 即可。

依赖为什么被锁得这么死（均已用 `pip download --python-version 38` 实测）：

- `pymupdf` 只能到 **1.23.26**，1.24+ 没有 cp38 轮子；
- `python-docx` 只能到 **1.1.2**，1.2.0 没有 cp38 轮子；
- `MarkupSafe` 只能到 **2.1.5**，3.x 要求 Python 3.9+；
- `PyInstaller` 用 **6.10.0**，更高的版本不再保证 cp38 支持。

构建脚本会核对解释器与依赖版本，不符直接拒绝构建。
若只是验证构建链路，可加 `--allow-unsupported-python` 绕过，但**产物名会带 `-unsupported`
且 SBOM 标明 `deliverable: false`，不可用于交付**。

### 2.5 Windows 7 目标机的两个系统补丁

Win7 机器上出现过启动失败，绝大多数是缺下面两个补丁，不是程序问题：

| 补丁 | 作用 | 缺失表现 |
|---|---|---|
| **KB4490628** | SHA-2 代码签名支持 | 双击 exe 无反应，或提示「不是有效的 Win32 应用程序」 |
| **KB2533623** | DLL 加载安全策略 | 启动时报「无法定位程序输入点」 |

这两个补丁由单位信息中心统一推送，一般已随历史更新安装。无法自行安装时联系信息中心，
**不要试图用替换 DLL 的方式绕过**——那会把一个可解释的问题变成不可解释的问题。

## 3. 构建流程

```bat
cd <项目根目录>

:: 1) 前置检查（不打包，20 秒内给出全部环境问题）
python tools\build_offline.py --check-only

:: 2) 完整构建（首次约 3–6 分钟）
python tools\build_offline.py
```

脚本按顺序做六件事，任一步失败即中止，不产出半成品：

1. **前置检查**：平台、位数、Python 版本、tkinter、三个运行依赖、PyInstaller、构建机污染提示。
2. **生成 SBOM**：`sbom.json`，列出每个依赖的版本与许可证。内网安全审计要求能回答「包里有什么」。
3. **写 Windows 版本资源**：使 exe 属性页可见版本号，软件登记时必需。
4. **调用 PyInstaller**（onedir）。
5. **冒烟测试**：运行产物内的 `cedas-cli.exe doctor`，校验退出码、关键输出与规则文件是否随包分发。
   **打包成功 ≠ 能运行**——tkinter 缺失与资源未打入这两类故障只在运行时暴露，
   必须在构建机上先跑一遍，不能等到内网现场才发现。
6. **生成交付 zip**：附 `离线安装说明.txt`、`sbom.json`、`SHA256SUMS.txt`。

产物：

```
dist/release/
  CEDAS-0.1.0-win7-win64.zip         交付介质用这个
  CEDAS-0.1.0-win7-win64/
    CEDAS/                      ← 解压后整个目录拷到目标机
      CEDAS.exe                 界面版
      cedas-cli.exe             排障版（带控制台）
      _internal/                解释器与依赖，勿手工改动
      数据说明.txt
    离线安装说明.txt
    sbom.json
    SHA256SUMS.txt
  build-report.json             体积、文件数、冒烟结果
```

## 4. 为什么是 onedir 而不是 onefile

需求文档建议 PyInstaller 单文件 EXE。本项目**改为单目录**，理由是会直接导致部署失败的三件事：

1. **法院终端管控**。这类机器普遍装有准入 / 桌面管控 / 加密客户端，其策略常见「禁止从 `%TEMP%`
   执行二进制」。onefile 每次启动都把全部内容解压到 `%TEMP%\_MEIxxxxxx` 再执行，
   在这类机器上的表现是**双击无反应，且不弹任何错误**。这种故障在现场极难描述、更难远程定位。
2. **冷启动**。本项目解压量约 100MB+（PyMuPDF 的扩展模块单独就 20MB 以上），
   在老机械硬盘上 onefile 每次启动需 5–15 秒；onedir 直接从磁盘加载，通常 2–3 秒。
3. **杀毒误报**。单文件自解压行为在启发式规则下容易被判为「投放器」而拦截。

代价是产物为目录而非单文件，已由 zip + 说明文档消化。若确实需要单文件分发形式，
可对 `dist/release/CEDAS-<version>-win7-win64/` 再做一次压缩自解压包，但**解压目标必须是固定目录**，
不要用「解压到临时目录运行」的模式。

## 5. 目标机部署

```
1. 把 CEDAS-<version>-win7-win64.zip 拷入内网，解压。
2. 将 CEDAS 文件夹整体复制到目标位置，建议 D:\CEDAS（避免 C:\Program Files，见 6.4）。
3. 双击 CEDAS.exe。
4. 如需快捷方式：右键 CEDAS.exe → 发送到 → 桌面快捷方式。
```

首次运行会在 `CEDAS\data\` 下自动建立 `cedas.db`、`samples`、`truth`、`output`。
无需管理员权限，不写注册表，不装服务，不修改系统目录。

**清洁卸载**：删除整个 `CEDAS` 文件夹即可，无残留。

### 验收清单（目标机实测）

| 项 | 方法 | 通过标准 |
|---|---|---|
| 可启动 | 双击 `CEDAS.exe` | 3 秒内出现窗口 |
| 环境完整 | 运行 `cedas-cli.exe doctor` | 输出「自检通过」 |
| 数据可写 | doctor 的「可写性」一行 | 显示正常 |
| 全程离线 | 断网 / 拔网线后重跑上述两项 | 结果不变 |
| 处理耗时 | 单份判决书走完抽取 + 生成 | 记录实测值，与业务方确认阈值 |
| 内存峰值 | 任务管理器观察 | 记录实测值，建议 ≤250MB |

`doctor` 的输出请截图存档——它是后续所有问题的第一手材料。

## 6. 现场可能遇到的拦截

这一节是实施经验，按发生概率排序。**未在此列出的问题，一律先跑 `doctor` 拿信息**。

### 6.1 双击无反应，也没有报错

按顺序查：

1. 是否被终端管控软件拦截（查安全软件日志、找信息中心加白名单）。
2. 是否杀毒软件把 `CEDAS.exe` 或 `_internal\` 下的 DLL 隔离了（查隔离区）。
3. 用 `cedas-cli.exe doctor` 启动，看是否有控制台报错。

### 6.2 提示缺少 VCRUNTIME140.dll

Win10 自带 UCRT，正常不会出现。若出现，说明目标机是早期 Win10 且未打补丁，
或系统目录被精简过。处理：从构建机 `C:\Windows\System32\` 复制 `vcruntime140.dll`、
`vcruntime140_1.dll` 到 `_internal\` 目录（PyInstaller 通常会自带，缺失时手工补）。

### 6.3 杀毒软件报毒

PyInstaller 产物被误报是行业常态。三条处理路径，优先级从高到低：

1. 提交单位信息中心加白名单（需提供 `sbom.json` 与源码，本项目已备）。
2. 使用单位内部的代码签名证书对 exe 签名，可显著降低误报率。
3. 换用「便携 Python + 源码目录 + 启动 bat」的降级方案——但同样会被拦，不推荐。

**不要用 UPX 压缩来减小体积**，它会显著提高误报概率。spec 中已显式 `upx=False`。

### 6.4 数据写不进去

若把程序放在 `C:\Program Files\`，普通用户对该目录无写权限，台账与生成的文书会写入失败。
两个办法：

- 移到 `D:\CEDAS` 等用户可写位置（推荐）。
- 设置环境变量 `CEDAS_HOME` 指向可写目录，程序的数据全部落到那里。

```bat
setx CEDAS_HOME "D:\CEDAS数据"
```

### 6.5 生成的文书打不开 / 版式错乱

目标机 Office/WPS 版本低（已知情况）。本项目**只生成 `.docx`，不调用 Office**，
所以生成环节与办公软件版本无关。打不开通常是以下原因：

- 模板本身用了低版本不支持的特性（如新版域、内容控件）→ 换用低版本另存的模板。
- 模板是 `.doc` 而非 `.docx` → 系统会提示，须先另存为 `.docx`。

### 6.6 U 盘拷不进去

多数法院内网禁用 U 盘，需走「内外网文件交换系统」或刻盘。zip 内附 `SHA256SUMS.txt`，
拷入后校验：

```bat
certutil -hashfile CEDAS-0.1.0-win7-win64.zip SHA256
```

与清单首行一致才算完整传输。

## 7. 规则升级：不需要重新打包

内网最大的运维痛点是「改一行规则要重新走一遍拷贝审批」。本项目的规则是外置 JSON
（ADR-002），加载时按**目录优先级 + 同名文件覆盖**处理（ADR-011）：

```
<安装目录>\_internal\resources\rules\     ← 基线，随包分发，只读
<安装目录>\resources\rules\               ← 现场补丁区，优先级更高
```

升级流程：

1. 把新规则文件放到 `CEDAS\resources\rules\`（目录不存在则新建）。
2. **文件名必须与基线中的同名**，否则会成为一条新增规则而非覆盖。
3. 重启程序生效。

覆盖粒度是「整个文件」而非「单条规则」。这样「基线有、补丁删」的情形才表达得出来；
若按条覆盖，规则库会变成无法推理的叠加层。

回滚同样简单：删掉补丁文件，程序回到基线规则。

> 提醒：规则改动属于**影响司法文书生成**的变更，须按 `05-开发与交接手册` 的回归流程走一遍，
> 不能直接在生产机上改。建议先在测试机上用留出集样本验证。

## 8. 版本并存与回滚

升级程序时不要覆盖旧目录，改为并存：

```
D:\CEDAS\            ← 旧版本，保留一个版本周期
D:\CEDAS-0.2.0\      ← 新版本
```

两份程序各自带独立 `data\`，互不影响。切回旧版只需重新双击旧目录的 exe。
旧版本确认稳定一个周期后再删除。

## 9. 本方案不能解决的事

诚实列出边界，避免在验收时才发现：

1. **无代码签名证书时，无法避免部分安全软件的误报。** 只能走白名单流程。
2. **无法在不接触目标机的情况下排查问题。** 内网隔离意味着所有诊断都靠 `doctor` 输出与截图，
   建议交付时给使用人做一次 5 分钟培训，重点教「怎么跑 doctor、怎么截图」。
3. **Win7 机器缺系统补丁时，程序起不来，这不是程序能修的。** 见 2.5 的 KB4490628 / KB2533623。
   另外 Win7 机器往往更老，2GB 内存下界面里的「全文高亮」可能需要关掉，属预期降级。
4. **Office 2007 及更早打不开 `.docx`。** 程序只保证生成合规的 docx，不负责目标机有没有能打开它的软件。
   Office 2007 需装兼容包，Office 2003 基本只能靠 WPS。这一项必须在试运行前逐台确认，
   否则会出现「文书生成成功但打不开」，比程序报错更难解释。
5. **无法自动更新。** 每次程序升级仍需人工拷贝，只有规则可现场替换。
6. **不保证与其他安全软件共存。** 与加密客户端（透明加密）共存时，生成的 docx 可能被自动加密，
   导致其他机器无法打开——这属于单位策略问题，需在试运行阶段确认。
7. **Python 3.8 已停止维护。** 这不是部署问题，是长期维护成本：不能靠升级依赖修漏洞，
   要升级就得放弃 Win7。见 ADR-013。
