# 02 · 系统架构

> 实现结构的唯一权威。改动分层或接口前先改本文并追加 ADR。
> 最后更新：2026-10-31

---

## 1. 分层

```
              ┌──────────────────────────────────────┐
              │  ui/        表现层（Tkinter）           │
              │  台账列表 · 复核面板 · 任务进度          │
              └───────────────┬──────────────────────┘
                              │ 只调用应用服务，不写正则、不碰 SQL
        ┌─────────────────────┼─────────────────────┐
        │                     │                     │
┌───────▼──────┐   ┌──────────▼────────┐   ┌────────▼───────┐
│ storage/     │   │ render/            │   │ extract/       │
│ SQLite 台账   │   │ 映射表 · docxtpl   │   │ 锚点 · 规则注册 │
│ 归档路径      │   │ 占位符校验          │   │ 字段字典装配    │
└───────┬──────┘   └──────────┬─────────┘   └────────┬───────┘
        │                     │                      │
        │            ┌────────▼──────────────────────▼───────┐
        │            │ ingest/  输入与清洗                    │
        │            │ PDF 通道（生产） · TXT 通道（开发）      │
        │            │ → RawBlock[] → ProseParagraph[]        │
        │            └────────────────┬──────────────────────┘
        │                             │
        │            ┌────────────────▼──────────────────────┐
        └────────────► calc/  刑期解析 · 折抵 · 一致性校验    │
                     └────────────────┬──────────────────────┘
                                      │
                     ┌────────────────▼──────────────────────┐
                     │ domain/  数据模型与枚举（零外部依赖）    │
                     └───────────────────────────────────────┘
```

**依赖方向单向向下，禁止反向 import。**

- `domain` 不得 import 任何上层，也不得依赖第三方库（只用标准库）。
- `calc` 不得 import `ingest`——计算层不认识文本，只认识数值与日期。
- `ui` 不得直接写正则或 SQL，必须经 `extract` / `storage` 的公开接口。

## 2. 双通道输入（关键设计）

生产与开发走两条通道，**但必须汇入同一个清洗层**，否则在 TXT 上调出的规则到了真实 PDF 上会失灵。

```
生产：判决书.pdf ──► pdf_reader ──► RawBlock[page, text, font_size, bbox, page_height]
                                                        │
开发：样本.txt  ──► txt_reader ──► RawBlock[page=None, font_size=None] ──┐
                                                        │                │
                                                        ▼                ▼
                                                   cleaner（唯一清洗实现）
                                                        │
                                                   ProseParagraph[]
```

| 通道 | 用途 | 可用信息 | 能力降级 |
|---|---|---|---|
| PDF | **唯一生产通道** | 页码、字号、坐标、页高 | 无 |
| TXT | 仅规则开发与回归 | 仅文本顺序 | 无页码、无字号、无坐标、无页高 |

### 2.1 TXT 通道的四项能力降级（必须写进测试预期）

1. **页码缺失** ⇒ `ProseParagraph.page = None`，`FieldValue.provenance.page = None`，复核界面显示「段落 N」。
2. **字号缺失** ⇒ 标题判定不能用字号，只能退回「短行 + 无句末标点 + 后续有正文」的启发式。
3. **位置判据失效** ⇒ 页眉页脚只能靠「跨页重复率」判定。PDF 通道另有一套更准的判据：位于页面顶部 10% 且字号小于正文，或字号与正文相当但跨页重复（`cleaner._header_keys`）。
4. **页高缺失** ⇒ 无法把纵坐标换算成页面相对位置。这是第 3 条判据不能跨通道复用的直接原因：同样的 y=40，在 A4 上是页眉，在五寸小票上是正文。

> **风险登记**：这是本项目最大的技术风险。缓解措施见 §6。

### 2.2 样本采集的反直觉要求

采集 TXT 时**不要手工删除页眉页脚**。理由：如果样本被人工清理干净，规则会在「无噪声」的数据上通过，而生产 PDF 的噪声仍在。样本必须保持原始脏度，才能让清洗层被真正训练到。

## 3. 数据流（单份判决书）

```
1  ingest     读取 → RawBlock[] → 清洗 → ProseParagraph[]
2  extract    锚点定位（首部 / 主文 / 落款）
              按锚点区间套规则 → 逐字段 FieldValue
              多被告人切分 → Defendant[] 骨架
3  calc       中文刑期 → 月数；起算日 + 刑期 − 1 → 届满日
              折抵换算；与文本载明起止日比对 → consistency
4  review     人工复核（可修正），修正值进 corrections[]
5  render     按文书类型取映射表 → 组装上下文 → docxtpl 渲染
6  storage    规范命名 → 写归档目录 → 台账落库
```

阶段 2 与 3 之间不落盘，4 之后才持久化——避免产生半成品台账记录。

## 4. 接口契约

契约是**跨 Agent 协作的边界**。修改签名须同步改本文与调用方测试。

```python
# ingest/base.py
def read(path: Path) -> list[RawBlock]: ...
@dataclass
class RawBlock:
    text: str
    page: int | None          # TXT 通道为 None
    font_size: float | None   # TXT 通道为 None
    bbox: tuple[float, float, float, float] | None
    page_height: float | None # TXT 通道为 None；页眉判定换算相对位置用

# ingest/cleaner.py
def clean(blocks: list[RawBlock]) -> list[ProseParagraph]: ...

# extract/anchors.py
def locate(paragraphs: list[ProseParagraph]) -> Anchors: ...
@dataclass
class Anchors:
    head: slice          # 首部区间
    body: slice          # 主文区间（"判决如下" 之后）
    tail: slice          # 落款区间

# extract/extractor.py
def extract(paragraphs: list[ProseParagraph]) -> ExtractionResult: ...

# calc/sentence.py
def compute_end_date(start: date, months: int) -> date: ...
def offset_days(principal: PrincipalType, custody_days: int) -> int: ...

# render/template.py
def render(template: Path, context: dict, out: Path) -> RenderReport: ...
```

`ExtractionResult` 内含 `case: Case`、`defendants: list[Defendant]`、`warnings: list[Warning]`。

## 5. 规则库

外部 JSON，**不随程序版本锁定**，允许现场热替换。

```
resources/rules/
├── head_case_no.v1.json
├── head_defendant.v1.json
└── ...
```

每条规则含：`rule_id` `field` `layer` `pattern` `version` `evidence` `updated_at`。

- `evidence` 必填——写明依据哪份样本的哪段文字。缺 `evidence` 的规则不予入库。
- 启动时校验 schema 版本，不匹配则拒绝加载并给出明确错误，不做静默降级。

### 5.1 两层加载（基线 + 现场补丁）

```
<安装目录>/_internal/resources/rules/   基线，随包分发，只读
<安装目录>/resources/rules/             现场补丁区，优先级更高
```

按**文件名**合并：补丁区存在同名文件即整体替换基线中的那一份，否则基线生效。
加载逻辑在 `extract/rule_loader.load_rules_from()`，搜索路径由 `config.rule_search_dirs()` 提供。

设计要点：

- 覆盖粒度是「文件」而不是「单条规则」。按条覆盖无法表达「基线有、补丁删」，
  规则库会退化成无法推理的叠加层。
- 两个目录出现相同 `rule_id` 时直接报错。这是把「文件名写错导致变成新增规则」变成显式失败。
- 不直接改 `_internal`：那是安装产物，用户改动无记录、易被下一次覆盖抹掉。

### 5.2 路径模型（只读 / 可写必须分开）

| 常量 | 打包后的值 | 用途 |
|---|---|---|
| `BUNDLE_DIR` | `_internal`（即 `sys._MEIPASS`） | 只读资源。**退出后可能被删除，绝不可写** |
| `APP_HOME` | exe 所在目录（可用 `CEDAS_HOME` 覆盖） | 数据库、生成文书、归档、规则补丁 |

早期实现用单一 `ROOT_DIR` 同时承担两者，导致打包后台账与文书写进临时目录、程序一关即丢。
详见 ADR-011，`config.py` 的模块注释亦写明「切勿回退」。

## 6. 风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| TXT 上验证的规则在 PDF 上失效 | 命中率虚高，生产不可用 | ① 样本保留原始噪声；② `tools/make_sample_pdf.py` 造合成 PDF，先断言两通道逐段一致，再在 ≥10 份真 PDF 上回归；③ 把「PDF 回归」设为阶段 2 的退出门槛 |
| 页眉页脚误删正文 | 字段整段丢失，且难察觉 | PDF 用「顶部 10% + 字号小于正文」或「跨页重复」两条独立线索；TXT 退回重复计数；对首部区间加保护性白名单 |
| 规则过拟合样本 | 换法院即失效 | 留出集按「法院 + 年份」分组；diff 审查硬编码 |
| 旧机性能不达标 | 部署失败 | 尽早实测；RSS 预算 200MB（按 2GB 目标机）；界面分页加载，不整表加载 |
| 模板占位符失配 | 生成成功但文书不可用 | 导入时校验 + 生成前二次校验，未解析即阻断 |

## 7. 错误处理原则

1. **抽取失败不阻断流程，阻断生成。** 单字段缺失记 `missing_reason` 并进复核队列；核心字段（P0）缺失才阻断该份文书的生成。
2. **不静默降级。** 规则库版本不匹配、模板占位符未解析、编码识别失败——一律显式报错，不猜。
3. **异常不吞。** 除 UI 事件回调外，禁止裸 `except:`；捕获后必须记日志并向上传递或明确处理。
4. **日志不含正文。** 只记段落索引与字段名，不记判决书原文，避免日志文件成为泄密源。

## 8. 目录职责速查

| 目录 | 职责 | 禁止 |
|---|---|---|
| `domain/` | 数据模型、枚举 | 依赖第三方库、访问文件 |
| `ingest/` | 读取与清洗 | 做字段抽取、写数据库 |
| `extract/` | 锚点、规则、装配 | 做日期运算、渲染文书 |
| `calc/` | 刑期与日期计算 | 读文本、依赖 ingest |
| `render/` | 模板映射与渲染 | 直接读 PDF |
| `storage/` | 台账与归档 | 生成文书内容 |
| `ui/` | 交互与展示 | 写正则、写 SQL |
