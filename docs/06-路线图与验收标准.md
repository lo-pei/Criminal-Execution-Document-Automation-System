# 06 · 路线图与验收标准

> 阶段划分已按 ADR-009 调整为**垂直切片优先**，与原始需求文档的横向推进不同。
> 最后更新：2026-10-31

---

## 1. 为什么改

原计划按阶段 0→6 横向推进：先全量清洗、再全量抽取、再全量映射。问题在于字段字典与模板映射的真实耦合要到最后才暴露，届时清洗层与规则层已定型，改动成本最高。

改为：**先在一个小范围内端到端打通一次**，让耦合问题提前暴露，再横向复制。

## 2. 垂直切片的定义

| 维度 | 取值 |
|---|---|
| 法院 | 1 个 |
| 判决书 | 20 份，同一模板版本 |
| 文书类型 | 1 类：执行通知书 |
| 链路 | PDF/TXT → 清洗 → 抽取 → 字段字典 → 生成 docx → 台账 → 复核定位 |

## 3. 验收指标

| # | 指标 | 阈值 | 计量口径 |
|---|---|---|---|
| V1 | 核心字段命中率 | ≥98% | 分母 = 真值集中「该字段存在且应被抽出」的实例数，**不是总份数** |
| V2 | 辅助字段命中率 | ≥90% | 同上 |
| V3 | 误抽率 | ≤2% | 抽出值与真值不符的实例 / 抽出总实例 |
| V4 | 单份端到端耗时 | ≤30 秒 | 提取→清洗→抽取→生成，不含人工打开 Office |
| V5 | 进程内存峰值 | ≤250MB | 任务管理器实测 |
| V6 | 字段可溯源率 | 100% | 已抽字段中能定位到页码/段落的比例 |
| V7 | 生成文书可用率 | 100% | 占位符全部解析、无残留 `{{}}` |

**核心字段清单**（用于 V1 分母，需业务方最终确认）：案号、法院名称、被告人姓名、性别、出生日期、身份证号、罪名、主刑、刑期、决定执行刑期、是否缓刑、刑期起算日、刑期届满日、判决日期、生效日期、羁押场所。

## 4. 阶段与退出门槛

### 阶段 0 · 前置确认

产出：样本采集 + 真值表 + 环境核对。

退出：① 20 份样本通过 `sample_lint`；② 真值表 A/B/C/D 四表填满且行序对齐；③ 办公软件版本号确认；④ 字段字典 spec 的 10 项待确认事项全部有结论。

### 阶段 1 · 清洗层验证

产出：`ProseParagraph[]` 在 20 份样本上人工核对通过。

退出：三个锚点（`判决如下`、`即自…起至…止`、案号行）定位成功率 ≥95%。

> **注意**：清洗层的问题会伪装成规则层的问题。锚点定位率不达标时，先怀疑清洗，不要急着改正则。

### 阶段 2 · 规则层与双通道回归

产出：A/B 组规则 + 多被告人切分 + C 组计算校验。

退出：① 训练集上 V1–V3 达标；② **`pdf_reader` 实现并在 ≥10 份真实 PDF 上回归，结论与 TXT 通道一致**（ADR-005 的风险缓解，硬门槛）。

### 阶段 3 · 模板映射与生成

产出：执行通知书模板 + 映射表 + 占位符校验器。

退出：V7 达成；10 份样本端到端生成，人工核对字段值与原文一致。

### 阶段 4 · 台账与复核界面

产出：SQLite 台账、检索、复核面板（点击字段高亮原文段落、可修正）。

退出：V6 达成；修正值能落库并进入规则候选队列。

### 阶段 5 · 打包与旧机实测

产出：PyInstaller 单文件夹发行包 + 一页纸操作说明。

退出：目标机双击即用、断网可用；V4、V5 达标；冷启动耗时记录在案。

### 阶段 6 · 试运行

产出：小范围真实案件试运行报告；规则维护流程文档。

退出：核心字段错误率可统计、可归因、可修复。

## 5. 优先级

| 级别 | 内容 |
|---|---|
| P0 | 阶段 0、1、2、3、5 —— 缺任一，系统不成立 |
| P1 | 阶段 4 —— 保障可用性与可追溯 |
| P2 | 轻量模型补抽 —— 已推迟（ADR-008），仅保留接口 |

## 6. 横展条件

垂直切片验收通过后才进入横展。横展按「模板 → 法院 → 案件类型」顺序，一次只扩一个维度，每扩一次跑全量回归。

不在横展范围内的：未成年人案件（封存与隐名）、单位犯罪（主体模型需扩展）、财产刑缴纳状态（属执行阶段数据）。
