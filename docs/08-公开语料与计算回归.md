# 08 · 公开语料与真实文书回归

> 适用对象：接手抽取规则与刑期计算的人。
> 前置阅读：`00-字段字典`（C 组）、`02-系统架构`（§2 输入层）、`05-开发与交接手册`（§4 下一个动作）。

---

## 1. 结论先行

用 36 份真实一审刑事判决书的主文做回归，得到三条结论：

1. **计算规则成立。** 17 份写了刑期起止日的文书里，16 份与「起算日 + 刑期 − 1 日」完全吻合（94%）。
2. **唯一的例外不是 bug。** （2026）鄂9006刑初384号是数罪并罚、前罪已羁押六天，起止日按实际羁押日扣减，
   本就不适用那条公式。
3. **过半主文不写起止日。** 19 份（53%）只写「刑期从判决执行之日起计算」，把起止日的计算留给执行环节。
   这是「生效日期必须人工录入」的实证依据，不是设计者的保守假设。

> 语料是抽样，不是穷尽检索。它能证明「规则在真实写法上跑得通」，不能证明「全国都这么写」。

---

## 2. 为什么先用公开语料

原计划的 20 份样本判决书仍在等业务方提供（保密原因，只能给手工提取的 TXT）。
但计算层的正确性**不能靠合成数据自证**——合成样本是我按自己理解的文书样式写的，
用它验证我自己写的规则，等于自己给自己出考卷。

公开裁判文书解决的是这个循环：主文里「判处有期徒刑四年六个月……即自2026年5月12日起至
2030年11月11日止」这句话，**起止日是法院写死的，不是算出来的**，正好可以当金标准反算。

所以本阶段的目标不是「补样本」，而是**换一个独立来源，验证 `calc` 层**。

## 3. 语料构成

| 项 | 说明 |
| :--- | :--- |
| 来源 | 北大法宝·司法案例库（MCP 检索接口），逐条保留原文链接 |
| 筛选 | 一审 / 判决书 / 基层人民法院 / 审结日 2026 年 9–10 月 |
| 罪名 | 盗窃罪 10 条、危险驾驶罪 7 条、故意伤害罪 10 条、诈骗罪 9 条 |
| 有效条数 | 36（剔除 3 条：2 条主文为空、1 条字段错乱抓到法条原文） |
| 存放 | `data/public-corpus/cases.jsonl`，字段说明见同目录 `README.md` |

罪名选择的依据是**刑罚形态的覆盖率**，不是案件数量：危险驾驶罪几乎全是拘役 + 缓刑 + 罚金；
盗窃与诈骗覆盖长期徒刑与罚金；故意伤害覆盖缓刑与实刑的分布。四类合起来把
「有期徒刑 / 拘役 / 缓刑 / 罚金 / 数罪并罚」五种主文形态都占到了。

## 4. 真实文书暴露的六个形态

### 4.1 「一个月十五日」是一个独立分量 —— 已修，此前差 15 天

（2026）皖0881刑初147号原文：「判处拘役一个月十五天……自2026年9月30日至2026年11月13日止」。

旧实现 `parse_term` 只取年月两个分量，「十五日」被整体丢弃，算得 2026-10-29，**差 15 天**。
这类写法在拘役案件里很常见（本批 3 条），且「日」「天」两种字都有人用。

修复要点不只是加个字段，还有**运算顺序**：先加月、再加日、最后减 1 日。

| 顺序 | 结果 | 是否吻合 |
| :--- | :--- | :--- |
| 先加月 → 再加日 → 减 1 日 | 2026-11-13 | ✅ |
| 先加日 → 再加月 → 减 1 日 | 2026-11-14 | ❌ 差一天 |

### 4.2 过半主文不写起止日

19/36 条只写「刑期从判决执行之日起计算，判决执行以前先行羁押的，羁押一日折抵刑期一日」，
**没有起止日**。这类案件里，起止日由执行环节按判决生效日推算，正是执行通知书要填的内容。

对系统的直接影响：C 组的「生效日期」不是可选项。抽取不到起止日时，界面必须拦住，
让录入人自己填生效日，而不是替他从判决日或送达日猜一个。

### 4.3 折抵有两种写法，一种给了起算日，一种没给

- **给了起算日**：「经折抵后，侯某冰的刑期自2026年10月10日起至2026年12月9日止」（川3402刑初193号）
- **只给折抵天数**：「羁押一日折抵刑期一日，折抵刑期4日」（皖1623刑初642号）

第一种可以直接取起算日；第二种必须回到首部取羁押起始日。两者都不能用「判决日」顶替。

### 4.4 数罪并罚：只有「决定执行」是最终刑期

（2026）云0304刑初82号：「犯诈骗罪，判处有期徒刑十三年……犯非法采矿罪，判处有期徒刑十个月……
**决定执行有期徒刑十三年**」。

一个句子里有三次「判处」、一次「决定执行」。若按「第一个判处」取值，后续所有计算都错。
工具里因此把「决定执行」设为最高优先级，只有找不到时才退回「第一处判处」。

### 4.5 缓刑案的主刑仍要写，但不起算

缓刑判决照样有「判处有期徒刑三年，缓刑三年」，但**没有起止日**，只写「缓刑考验期限自判决确定之日起计算」。
执行通知书对这类的处理与实刑不同（不起算刑期、不填羁押折抵），模板分支必须区分，
不能拿实刑模板套。

### 4.6 上游数据会脏

被剔除的（2026）新4202刑初163号，「裁判结果」字段里装的是一段刑事诉讼法条文，
不是判决主文；另有 2 条该字段直接为空（"库里没有裁判主文"）。

这说明**任何依赖第三方摘要的环节都要能识别空值与错位**。本项目生产链路不吃第三方摘要，
但这条经验适用于后续任何数据对接。

## 5. 回归结果

```bash
python tools/corpus_regress.py          # 人读表格
python tools/corpus_regress.py --json   # 机器读
python tools/corpus_regress.py --strict # 出现不吻合时退出码 1
```

| 判定 | 条数 | 含义 |
| :--- | ---: | :--- |
| MATCH | 16 | 复算值与文书载明一致 |
| MISMATCH | 1 | 数罪并罚、前罪已羁押，起止日按实际羁押日扣减，非计算错误 |
| NO_DATE | 19 | 主文只写「从判决执行之日起计算」，无起止日可比 |
| UNPARSED | 0 | — |

这四条判定已固化进 `tests/test_corpus_regress.py`，作为**计算层的防回退闸门**：
吻合率低于 90%、出现无法解析的主刑、或「一个月十五天」那条不再 MATCH，测试就会红。

## 7. 还没解决的

- **元典智库未取得数据。** 连接器已授权，但本会话未暴露可调用的检索工具；其网页端需登录。
  目前语料全部来自北大法宝一个来源，**没有交叉来源校验**。
- **只有主文，没有首部。** 语料里没有被告人身份、住址、羁押场所、强制措施段，
  因此 B 组的身份字段抽取仍未被真实文书验证过。
- **管制、单处罚金、剥夺政治权利、无期徒刑没有样本。** 这四类主文形态目前只有合成测试覆盖。
- 境外/涉外案件、单位犯罪、未成年人案件均未纳入。

## 8. 需要业务方确认的六件事（真值表里填）

这六项无法从公开文书推出，只能由办案人员定口径。已写进 `data/truth/00-真值填写表.xlsx` 的待确认区：

| # | 待确认 | 为什么必须问 |
| :--- | :--- | :--- |
| 1 | 起算日取**拘留日**还是**逮捕日** | 文书只说「先行羁押之日」，两段羁押中间常有一天间隔 |
| 2 | 生效日期怎么定：送达日 + 上诉期届满日？还是法院另出证明 | 直接决定起止日，差一天即错 |
| 3 | 上诉期最后一日遇节假日是否顺延 | 同上，且各地做法可能不同 |
| 4 | 执行通知书里刑期起止的**书写格式**（「自X年X月X日至Y年Y月Y日止」还是分栏填） | 模板占位符要按实际格式设计 |
| 5 | 缓刑案件是否也走本系统，还是另有文书 | 决定模板分支要不要做 |
| 6 | 数罪并罚、前罪已羁押的案件，起算日如何取 | 公开文书显示各地扣减方式不一致 |
