# 字段字典 spec v0.1（CEDAS）

> 状态：草案，待业务方逐条确认
> 用途：① 清洗层与抽取层的输出契约；② 模板映射表的字段来源；③ 标注规范与 gold set 的列定义；④ 验收指标的计量口径。
> 约定：所有标注为 `【待确认】` 的条目必须在阶段 0 的业务会议上给定结论，不得由开发侧默认取值。

---

## 0. 数据模型总览

判决书是"一案多人、一人多罪"的层级结构，字段字典必须按此建模，不能用扁平 key-value。

```
Case（案件，1）
  ├─ case_no / court / 程序性字段（D 组）
  └─ Defendant[]（被告人，n）
        ├─ 身份与强制措施（A 组）
        ├─ Crime[]（罪名，m≥1）       ← 数罪并罚时 m>1
        │     └─ 该罪主刑 + 附加刑
        ├─ merged_sentence（决定执行刑期）  ← m>1 时必有，m=1 时等于该罪刑罚
        └─ 刑期计算（C 组）
```

`Crime[]` 这层是 v0.1 相对需求文档的主要修正：需求文档把"罪名、刑种刑期"当作标量，遇到数罪并罚（一人犯数罪，各罪分别量刑后决定执行）会直接失效。

## 1. A 组：标识与主体

| 字段 | 中文名 | 类型 | 合法形态 | 必需性 | 缺失行为 |
|---|---|---|---|---|---|
| `case_no` | 案号 | string | `[（(]\d{4}[）)]<代字>刑(初\|终\|再\|更\|抗)\d+号` | P0 | 阻断，需人工录入 |
| `court_name` | 法院名称 | string | 首部标题行，以"人民法院"结尾 | P0 | 阻断 |
| `defendant_name` | 被告人姓名 | string | 2–15 字；曾用名/化名另存 | P0 | 阻断 |
| `gender` | 性别 | enum | 男 / 女 | P0 | 空置，复核补录 |
| `birth_date` | 出生日期 | date | `\d{4}年\d{1,2}月\d{1,2}日` | P0 | 见下注 |
| `id_number` | 公民身份号码 | string | 18 位（含 X） | P0 | 空置，复核补录 |
| `ethnicity` | 民族 | string | `X族` | P1 | 空置 |
| `domicile` | 住址 | string | 至下一个逗号/句号止 | P1 | 空置 |
| `education` | 文化程度 | string | 文盲/小学/初中/高中/大专/大学… | P2 | 空置 |
| `occupation` | 职业 | string | 自由文本 | P2 | 空置 |
| `criminal_record` | 前科/累犯 | object | `{recidivist: bool, prior: string}` | P1 | 视为无前科但标记低置信 |
| `custody[]` | 强制措施 | array | 见 1.1 | P0 | 视为未羁押但告警 |
| `in_custody` | 是否在押 | bool（派生） | 由 `custody[]` 推导 | P0 | — |

> **出生日期注**：部分判决书只写"现年 45 岁"而不给具体日期。此时不得用"判决年份 − 45"反推——反推值会污染 C 组刑期计算。规则：记 `null`，`missing_reason = "only_age"`，强制进人工复核队列。

### 1.1 `custody[]` 结构

强制措施在同一被告人身上可能有多段（刑事拘留 → 逮捕），必须存为有序数组，不得只留最后一段。

```json
[
  {"type": "刑事拘留", "organ": "XX市公安局XX分局", "start": "2023-03-01", "end": "2023-03-14"},
  {"type": "逮捕",     "organ": "XX市XX区人民检察院", "start": "2023-03-14", "end": null}
]
```

- `end = null` 表示截至判决时仍在押。
- `in_custody = true` 当且仅当存在 `type ∈ {刑事拘留, 逮捕}` 且 `end = null`。
- 取保候审、监视居住不产生羁押折抵（指定居所监视居住除外，见 §6.3）。

## 2. B 组：定罪与量刑

### 2.1 罪名与各罪刑罚

| 字段 | 中文名 | 类型 | 说明 |
|---|---|---|---|
| `crimes[].charge` | 罪名 | string | 取法定罪名表述，不带"犯""罪"以外的修饰 |
| `crimes[].principal_type` | 主刑种类 | enum | 管制 / 拘役 / 有期徒刑 / 无期徒刑 / 死刑 |
| `crimes[].term_months` | 该罪刑期（月） | int | 由中文刑期解析得出，见 §6.1；无期/死刑为 null |
| `crimes[].additional[]` | 该罪附加刑 | array | 见 2.3 |

### 2.2 决定执行刑期

| 字段 | 中文名 | 类型 | 说明 |
|---|---|---|---|
| `merged_sentence.principal_type` | 决定执行主刑 | enum | 同上 |
| `merged_sentence.term_months` | 决定执行刑期（月） | int | 单罪时等于 `crimes[0].term_months` |
| `is_combined` | 是否数罪并罚 | bool | `len(crimes) > 1` |

> **【待确认】** 数罪并罚中"总和刑期 / 执行刑期"的表述差异（如"总和刑期五年，决定执行四年"）在本地法院判决书中是否常见？若常见，需增 `total_term_months` 字段。

### 2.3 附加刑

| 字段 | 中文名 | 类型 | 合法形态 |
|---|---|---|---|
| `additional[].type` | 附加刑种类 | enum | 罚金 / 没收财产 / 剥夺政治权利 / 驱逐出境 |
| `additional[].fine_amount` | 罚金数额 | decimal | `人民币X万元` / `X元`，统一折算为元 |
| `additional[].fine_deadline` | 罚金缴纳期限 | string | "于判决生效后X日内缴纳" / "限本判决生效之日起X日内" |
| `additional[].confiscation` | 没收财产范围 | object | `{scope: 全部\|部分, amount}` |
| `additional[].political_rights_years` | 剥夺政治权利期限 | int（年） | 可附加"自刑满释放之日起计算" |

> **【待确认】** 财产刑执行移送表是否需要单独统计"已缴纳/未缴纳"？若需要，属执行阶段数据，不应由判决书抽取，需另设字段来源。

### 2.4 缓刑与关联事项

| 字段 | 中文名 | 类型 | 说明 |
|---|---|---|---|
| `probation.applied` | 是否适用缓刑 | bool | 文中有"缓刑"即 true，需排除"不适用缓刑"的否定表述 |
| `probation.probation_months` | 考验期（月） | int | 从"缓刑X年"解析 |
| `probation.start_rule` | 考验期起算 | const | 固定为"判决确定之日"，见 §6.4 |
| `recovery[]` | 追缴/退赔/返还 | array | 影响财产执行，模板按需取用 |
| `civil_compensation` | 附带民事赔偿 | decimal | 有则记金额 |

## 3. C 组：刑期计算

**本节字段一律为"计算值 + 校验值"，不得直接采信文本抽取结果。**

| 字段 | 中文名 | 类型 | 来源 |
|---|---|---|---|
| `custody_start` | 羁押起始日 | date | 取 `custody[]` 中最早一段的 `start` |
| `sentence_start` | 刑期起算日 | date | 在押：= `custody_start`；未在押：= 生效日/交付执行日（人工录入） |
| `sentence_end` | 刑期届满日 | date | 由 §6.2 计算 |
| `release_date` | 释放日 | date | = `sentence_end` + 1 日 |
| `offset_rule` | 折抵方式 | enum | `1:1` / `1:2` / `none`，由主刑种类决定 |
| `offset_days` | 折抵天数 | int | 派生 |
| `text_start_end` | 文本载明的起止日 | object | 仅用于校验，不作取值来源 |
| `consistency` | 一致性校验结果 | enum | `pass` / `mismatch` / `no_text_end` |

> `consistency = mismatch` 时必须告警并在复核界面高亮两处数值（计算值 vs 文本值），由人裁定。**禁止系统自动采用任一方。**

## 4. D 组：程序性字段（v0.1 新增）

需求文档缺失此组。执行通知书与结案登记表均需这些字段，而它们**大部分不在判决书正文中**，必须由录入或推算获得。

| 字段 | 中文名 | 来源 | 必需性 |
|---|---|---|---|
| `filing_date` | 立案日期 | 【待确认】判决书首部是否载明 | P1 |
| `judgment_date` | 判决日期 | 尾部"二〇二X年X月X日" | P0 |
| `service_date` | 送达日期 | 人工录入 | P0（未在押案件） |
| `effective_date` | 生效日期 | 人工录入或推算，见 §6.5 | P0 |
| `panel` | 审判组织 | "审判长X / 审判员X / 人民陪审员X" | P1 |
| `clerk` | 书记员 | 尾部 | P1 |
| `prosecutor_organ` | 公诉机关 | 首部"XX人民检察院" | P1 |
| `detention_place` | 羁押场所 | "现羁押于XX看守所" | P0（在押案件） |
| `delivery_organ` | 送达机关 | 人工选择（监狱/看守所/司法所） | P0 |
| `cause` | 案由 | 派生自 `crimes[].charge` | P1 |

## 5. 溯源与置信度

每个字段（含数组元素）附加元数据，与值同存：

```json
{
  "value": "2023-03-01",
  "page": 2,
  "para_index": 14,
  "snippet": "被告人张三于2023年3月1日被刑事拘留",
  "extractor": "rule:custody_v3",
  "confidence": 0.95,
  "corrections": []
}
```

规则：

1. `page` + `para_index` 指向清洗层输出的段落列表坐标，**不存字符级偏移**。段落级已满足复核需求，字符级映射会显著增加清洗层复杂度且易失效。
2. 多值字段（`crimes[]`、`custody[]`）的溯源挂在元素上，不挂在数组上。
3. 人工修正后保留原值于 `corrections[]`，供规则迭代分析，**不得覆盖**。

## 6. 刑期计算规则

> 以下条文依据需业务方核校后固化，代码中以常量表实现，不做运算期推导。

### 6.1 中文刑期解析

- 形态：`有期徒刑三年六个月`、`有期徒刑一年六个月`、`拘役六个月`、`管制二年`、`有期徒刑十年`、`无期徒刑`、`死刑`。
- 归一：年 × 12 + 月。允许"零X个月"写法，忽略"零"。
- 不得接受"三年半""一年零两个月"等非规范表述作为主路径，遇到记 `unparsed` 并告警。

### 6.2 届满日算法

```
届满日 = 起算日 + N年M月 − 1日
释放日 = 届满日 + 1日
```

- 月末日处理：起算日为 1 月 31 日、加 1 个月，取 2 月最后一日（28/29）。
- **必须减 1 日。** 这是此类系统最常见的一日之差错误来源：4 年有期徒刑自 2023-01-01 起算，届满日为 2026-12-31，释放日为 2027-01-01。

### 6.3 折抵规则

| 主刑 | 折抵 | 依据 |
|---|---|---|
| 管制 | 羁押 1 日折抵刑期 2 日 | 刑法第 41 条 |
| 拘役 | 1:1 | 刑法第 44 条 |
| 有期徒刑 | 1:1 | 刑法第 47 条 |
| 无期徒刑 / 死刑 | 不折抵 | — |
| 指定居所监视居住 | 管制 1:1；拘役、有期徒刑 2:1 | 刑事诉讼法第 76 条 |

### 6.4 缓刑

考验期自判决确定之日起计算，判决前羁押不予折抵。考验期起算需 `effective_date`，故缓刑案件同样依赖 D 组。

### 6.5 生效日推算（仅在人工未录入时提供建议值）

- 一审：`effective_date = service_date + 10 日`（届满日次日生效，且需无上诉、抗诉）。
- 二审：`effective_date = 宣判日`。
- 系统只能给出**建议值 + 推算依据**，落库前须人工确认。

## 7. 校验规则清单

| 编号 | 规则 | 触发结果 |
|---|---|---|
| V1 | `sentence_end` 与文本载明起止日不一致 | `consistency = mismatch`，告警 |
| V2 | `in_custody = true` 但 `custody_start` 缺失 | 阻断生成 |
| V3 | 缓刑案件 `merged_sentence` 为无期/死刑 | 逻辑冲突，阻断 |
| V4 | `sum(crimes[].term_months) < merged_sentence.term_months` | 逻辑冲突，阻断 |
| V5 | 罚金数额为空但附加刑含罚金 | 告警，复核补录 |
| V6 | `effective_date` 早于 `judgment_date` | 阻断 |
| V7 | 被告人姓名在首部与主文不一致 | 告警，双值展示 |

## 8. 待确认事项汇总（业务会议逐条过）

| # | 问题 | 影响 |
|---|---|---|
| 1 | 判决书是否载明立案日期 | D 组字段来源 |
