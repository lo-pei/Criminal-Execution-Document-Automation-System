# 12 · 样本族与覆盖场景

> `data/samples/` 下的 17 份样本**不是示例**，是**真实生效判决**，每一份对应一种
> 会让抽取出错的判决书结构。加样本之前先读第 5 节「怎么采集一份样本」，
> 否则采回来的只是一份更长的、训练不了任何东西的文件。

---

## 1. 为什么样本必须是真实判决

2026-10-31 这一版曾用 9 份**自编**样本覆盖结构多样性（一案多人、四种并罚形态、
附带民事、单位犯罪、无期）。当时的理由是「真实语料只有 1 份，覆盖不了这些结构，
又不能为了覆盖而伪造真实语料」。

这个理由站不住。自编样本能回答的问题只有一个——「这条规则被改坏时会不会有人
发现」；它回答不了「这条规则在真实文书上对不对」。而后者才是业务方要的。

换成真实判决后，**第一次跑就错了 8 处**，每一处都是自编样本永远不会暴露的：

| 现象 | 真实文书的写法 | 为什么自编时不会发现 |
| :--- | :--- | :--- |
| 案号抽空 | （2014）甬余刑初字第633号 | 自编时习惯写「刑初123号」，想不到还有「刑初字第633号」 |
| 被告人认不出 | 「被告人颜某。曾因犯盗窃罪……」 | 自编时按范式写「被告人张三，男，1985年……」 |
| 羁押日全空 | 「2013年9月28日因涉嫌抢劫罪被……刑事拘留」 | 自编时写「于2013年9月28日被刑事拘留」，正好是正则要的样子 |
| 罪名 2 个抽成 4 个 | 「被告单位某某公司1犯虚开增值税专用发票罪」 | 自编时不会想到单位判项也会被当成续段 |

写样本的人和写规则的人是同一个人、用同一套想象——这就是自编样本的根本问题。
不是「样本不够多」，是「样本和规则来自同一个错误的脑袋」。

因此从 2026-11-01 起，本项目的回归样本**全部以真实生效判决为基础**：

| 语料 | 数量 | 能回答什么 | 不能回答什么 |
| :--- | ---: | :--- | :--- |
| `data/samples/` 真实判决全文 | 12 | 抽取规则在真实文书上认不认得对 | 清洗层的软换行与页眉页码（见下） |
| `data/public-corpus/` 主文摘录 | 36 | 刑期计算口径与法院真实写法（见 `08`） | 首部、落款、多被告人归属 |
| `examples/` 合成基线 | 1 | 命令能否跑通、TXT/PDF 双通道是否一致 | 任何命中率结论 |

三者分工明确，**不得混用**：

- 真实判决用于**规则回归**（`tests/test_samples.py`）与**缺陷发现**。
- 合成基线只剩 `examples/S000` 一份，用于跑通命令、界面演示、以及 PDF 通道
  回归——因为真实判决是数据库导出的纯文本，**没有版式噪声**，清洗层的
  「软换行合并」「页眉页码剔除」在这批样本上一个都测不到。
- 真实语料仍要按 `04-样本格式与标注规范.md` 继续采集，用于命中率统计与留出集。

### 2.1 四种并罚形态的区别

S001 / S002 / S003 / S004 分别对应四个法条。区分它们不是为了在文书上写出来，
而是因为**起算日来源不同**——这是本系统里最容易被悄悄做错的一步：

| 形态 | 法条 | 判决书里的标志句 | 刑期起算日 | 本系统如何处置 |
| :--- | :--- | :--- | :--- | :--- |
| 数罪并罚 | 69 | 「数罪并罚，决定执行…」 | 本罪羁押起始日 | 自动算，标 `W-COMBINED` |
| 先并后减 | 70 | 「已经执行的刑期，计算在本判决决定的刑期以内」 | **前罪刑期起算日** | 停住，报 `E-START-COMBINED` |
| 先减后并 | 71 | 「与前罪**未执行**的…并罚」 | **本判决执行之日** | 停住，报 `E-START-COMBINED` |
| 撤销缓刑并罚 | 77 | 「撤销…宣告缓刑…的执行部分」、「…缓刑的缓刑宣告」 | **本判决执行之日** | 停住，报 `E-START-COMBINED` |

后三种一律要求人工填写起算日，理由见 ADR-016。

判定实现在 `extract/combination.py`，有两处设计是被真实样本逼出来的：

1. **认结构不认短语。** 撤销缓刑的写法有「撤销缓刑」「撤销本院…宣告缓刑…的
   执行部分」「…缓刑的缓刑宣告」「撤销…假释裁定」四种，枚举短语必然漏掉其中
   几种。改用「撤销」与「缓刑/假释」同现判定。
2. **主文优先，说理兜底，且说理要按人切句。** S002 的判据词只在「本院认为」段；
   S004 的说理段同一句写了两个人（宿某建撤销假释、张某祥撤销缓刑），整段拿去
   判定必然把一人的情形套到另一人头上。所以先看主文判项，判不出再看说理段里
   **提到本人**的那一句。

### 2.2 载明起止日：抽，但只作校验

12 份里 5 份在主文写了「即自X日起至Y日止」，7 份没写（与 `08` 的 36 份公开语料
53% 不载明一致）。载明值**只作校验，不作取值来源**（ADR-017），因为它等于
「起算日 + 刑期 − 羁押折抵 − 前罪已执行刑期」，后两项首部读不出来。

| 编号 | 载明情况 | 与推算的差 | 原文里的解释 |
| :--- | :--- | ---: | :--- |
| S001 | 两人各一处 | 0 | 起算日恰为到案日，无折抵 |
| S002 | 一处（止日 2022-11-10） | — | 起算日待人工填（前罪起算日） |
| S003 | 一处（止日 2017-01-25） | 4 天 | 「共折抵二十二日」（指定居所监视居住） |
| S004 | 两人各一处 | 167 天（张某祥） | 撤销缓刑，前罪已执行部分刑期 |
| S008 | 三人各一处 | 5 / 3 / 1 天 | 「折抵5日 / 3日 / 1日」 |

这三处差额都不是 bug，而是系统**没有输入**的两项：折抵天数与前罪已执行刑期。
所以校验只回答「差几天」，不回答「用哪一个」。差 22 天、5 天这样的数字要能看见，
承办人才知道「只是折抵，不是抽错了」。

抽的时候要挡掉三种同形不同义的「自…起至…止」：另查明里的**前罪刑期**、
**假释考验期**、**缓刑考验期**。S004 一句话里三种全有，按日期形状取必然抽错，
而且抽错不会有任何报错。

## 3. 真值放在哪里

不在 Excel 里，在 `tests/test_samples.py` 的 `SAMPLES` 常量里。每份样本一条记录：

```python
Sample(
    file="S002__苏0723刑初53号.txt",
    kind=CRIMINAL_JUDGMENT,
    people=(Person("张某", ("盗窃",), 30, CombinationKind.MERGE_THEN_DEDUCT),),
    blocked=("E-START-COMBINED",),
)
```

放进代码而不是 `data/truth/00-真值填写表.xlsx`，是因为 Excel 是给业务方填
**采集语料**真值用的，而这里是回归断言：它要和规则一起进版本库、一起 review，
规则改了而真值没改时，diff 里能立刻看出来。

**每个数字都是回判决书原文抄的，不是从抽取输出复制的。** 两者一旦混同，测试
就只是在验证「代码没变」，而不是「代码对」。这条在采集真实样本时尤其要守住——
从抽取输出复制真值，等于把 bug 固化成期望。

> `data/truth/` 的真值表仍按 `04-样本格式与标注规范.md` 填采集语料，互不影响。

## 4. 断言分两层

`test_defendants` 只看「有没有认对」，`test_blocking` 只看「认对之后能不能出文」。
分成两个测试函数，是因为失败时要知道是规则错还是判据错：

| 层 | 断言 | 失败意味着 |
| :--- | :--- | :--- |
| 抽取 | 被告人姓名与顺序、罪名元组、决定执行月数、并罚形态、缓刑考验期 | 规则或归属逻辑错了 |
| 阻断 | 给出生效日期后应阻断的**刑期类**码集合 | 阻断判据错了，或该放行的被拦下 |

阻断断言只看刑期类码（`E-START*`、`E-END`、`E-LIFE`，以及两个「没有刑罚可执行」的结论码
`E-EXEMPT`、`E-NO-VERDICT`）：

```python
TERM_BLOCKERS = ("E-START", "E-END", "E-LIFE", "E-EXEMPT", "E-NO-VERDICT")
```

身份信息缺失（`E-ID` / `E-BIRTH` / `E-GENDER`）不计入。真实判决书的公开版本
本来就不载身份证号，拿它当断言等于要求样本造假——17 份样本全都会红，而红的
原因和规则对错毫无关系。

另外几条单独的函数锁住最容易退化的行为，每一条都对应一次真实出错：

- `test_combined_start_is_never_guessed`：并罚案件不给起算日时 `start` 必须是
  `None`。S004 张某祥首部最早的羁押日是 2011-07-29——那是**前案**的拘留日，
  本案载明的起止是 2013-10-16 至 2024-05-01。取最早羁押日会多算两年三个月，
  而文书上看不出任何异常。
- `test_combined_start_by_hand`：指定起算日后届满日按「起算日 + 刑期 − 1 日」。
  两组期望值都是判决书原文载明的（S004 宿某建 2013-09-28～2024-09-27、
  S002 张某 2020-05-11～2022-11-10），不是推算出来的。
- `test_control_offsets_are_flagged`：管制必须提示填写羁押天数。S007 实际羁押
  14 天，应折抵 28 天；不提这一句，届满日会整体偏后。
- `test_unit_crime_is_reported` / `test_units_do_not_leak_into_natural_person`：
  单位犯罪要给 `A006`，且单位判项不得并进自然人的罪名表。
- `test_revocation_paragraph_is_not_a_conviction`：「撤销…缓刑宣告」那一项是
  被撤销的前罪，不是本案定罪。
- `test_measure_after_case_clause` / `test_year_is_inherited_from_non_measure_date`：
  强制措施正则的两处真实写法（日期与「被」之间夹案由、年份来自「抓获」那句）。

## 5. 怎么采集一份样本

1. **先想清楚它覆盖哪条规则。** 想不出来就不要采——重复覆盖同一结构的样本
   只会拖慢测试，不会提高信心。
2. **必须是真实生效判决。** 从数据库取全文，不改写案情、刑期、日期。姓名用
   公开渠道已化名的「某」；上游原文里的笔误（如法院层级写错）**按原样保留**，
   记进 `data/samples/README.md` 的「上游数据瑕疵」，不要顺手改对——改了就等于
   自己造样本。
3. **优先挑载明了刑期起止日的。** 有「即自X年X月X日起至Y年Y月Y日止」，就能拿
   原文当期望值，验证「起算日 + 刑期 − 1 日」；没有的话，期望值只能自己推，
   等于用规则验规则。
4. **定向检索，不要按案由撒网。** 要找先减后并就按援引法条检索
   （`刑法第七十一条`），比按「盗窃罪」翻一百页准得多。
5. **落盘后先跑体检**：`python tools/sample_lint.py data/samples`。
   数据库导出的文本用默认 `--source db`，PDF 全选复制的用 `--source pdf`，
   两种来源的噪声形态不同，判据也不同。
6. **再跑一遍抽取摘要**：`python tools/sample_report.py data/samples`，
   逐份回原文核对，确认「认对了」还是「规则错了」。这一步的判断本身就是
   这套样本的价值所在。
7. **在 `SAMPLES` 里加一条**，写清预期；同时在本文第 2 节的表里加一行。

## 6. 未覆盖的情形

以下情形在真实案件里存在，但当前既没有样本也没有规则。列出来是为了避免
「样本全绿 = 已覆盖」的误判。

第二轮补样本后已经覆盖、因而从这里移出的：再审改判（S014／S015／S017）、
未成年被告人（S014，不公开审理 + 法定代理人）、单位犯罪中的多个直接责任人
（S013，一人同时是两个单位的主管人员却只有一个判项）。

| 情形 | 为什么没做 | 加进来要先解决 |
| :--- | :--- | :--- |
| 死刑缓期二年执行 | 不出执行通知书（送监狱执行的是死缓，减刑后另判） | 与无期一样走 `E-LIFE`，但「缓期二年」是否要单独提示 |
| 二审只改其中一名被告人 | S017 是再审的同类结构，二审的写法可能不同 | 首部列全案当事人、主文只写被改判者的归属规则 |
| 主文锚点写「判决：」而非「判决如下」 | 尚未遇到主文用「判决：」的样本（S017 的原审引述用了「判决：」，但那不是本案主文） | `BODY_START_MARKERS` 是否要容错，容错到什么程度 |
| 涉黑、涉恶等超长文书（20 人以上、十余罪名） | 单份正文过长，采集后挤占上下文；S016 的 26 人只涉一罪 | 一次采集与核对的时间成本 |
| 「被告人A、B共同犯…」一句定两人 | 现在按姓名切分，一句两姓会让后一个人抽不到 | 一句多人的罪名与刑期分配规则 |
| 管制羁押折抵天数 | `compute_span(custody_days=...)` 已支持，缺「羁押天数」录入项 | 首部只记措施起点，解除日期要靠下一条措施反推；末段仍在押时无从确定。当前只提示 `W-CONTROL-OFFSET` |
| 羁押折抵天数的自动抽取 | 目前只做校验（`V1`/`V2`），不读「折抵5日」「共折抵二十二日」，也不回填 | 折抵写法有「折抵X日」「监视居住两日折抵刑期一日」「经折抵后」多种；管制还要 1:2 换算。要落成录入项，先确定界面放在哪一组 |
| 驱逐出境、剥夺政治权利 | 附加刑未抽取 | `AdditionalPunishment` 已有字段，缺规则 |
| 数罪并罚决定执行罚金总额 | 未抽取合并后的罚金 | 执行通知书是否要写罚金总额，需业务方定 |
| 附带民事赔偿金额 | 不抽取 | 执行通知书不涉及民事部分，暂不做 |

## 7. 一句话总结

样本的价值不在于「有多少份」，而在于**每一份都能让某条规则在写错时立刻报错**，
并且**它是真实的**。前一条决定样本有没有用，后一条决定这个「有用」是不是
真的。加样本时先问两句：这条规则被我改坏了，这份样本会不会红？这份文本是
法院写的，还是我编的？
