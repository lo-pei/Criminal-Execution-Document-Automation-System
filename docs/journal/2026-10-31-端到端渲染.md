# 端到端渲染与归档

## 1. 本次目标

把「判决书进 → 执行文书出」串成一条命令：`cedas render`。此前 `extract` 能给字段、
`render` 能填模板、`storage` 会算路径，但没人把它们接起来，也没人回答三个现场问题——
**该出几份、叫什么名、缺字段怎么办**。

顺带补上 D 组 4 个程序性字段（判决日期、审判组织、书记员、公诉机关）：执行通知书落款
必须有判决日期，而它此前一直是空字符串。

## 3. 为什么这样设计

**阻断优于残次。** 核心字段缺失不生成文书，而不是生成一份带空白的正式文书。理由很具体：
占位符被替换成空串后，看起来就像「本来就没这项」，没有任何痕迹提示它是残的。缺身份证号
的执行通知书送到看守所会被退回，而退回之前没人会怀疑它。

**起算日必须能看出是从哪推来的。** 判决书载明则用载明的；未载明退回生效日（`08` 实测
53% 的主文不写起止日）。这两条路径都合法，但复核的人必须能分辨。所以报告里有
`start_source`，并且推得的会附 `W-START-EFFECTIVE` 告警。

**归档与台账都收在 pipeline。** 界面和命令行都要出文书，若各自写命名规则，迟早出现
两套目录结构。`archive.py` 只提供「怎么拼」，pipeline 决定「拼什么」。

**合成模板是必需品，不是玩具。** 模板属受控材料不入库，但没有模板这条链在 CI 上根本
跑不起来。合成模板与真实模板同构（标题/案号/正文/逐格表格/落款），首行标注「示例·合成·
不得作为司法文书使用」，不会被误当正式文书。

## 4. 踩到的坑

| 现象 | 原因 | 处置 |
|---|---|---|
| 报告显示 6 月 1 日起算，文书起止两格空白 | `resolve_span` 返回新 `SentenceSpan`，没写回 `defendant.span`；映射表的派生字段读的是 `defendant.span` | 算完回写，并用回退场景的测试锁住 |
| `IndexError: list index out of range` | `config.REQUIRED_FIELDS` 里 `case_no` 不带 `case.` 前缀，`defendant.name` 带，按点号切分时越界 | `_present()` 统一处理两种写法 |
| 「二〇二三」解析成 3 | 复用了 `calc.cn_number_to_int`（位值读法：二千零二十三 → 3） | 年份**逐位**读、月日按**位值**读，两种读法分开实现，测试里显式断言 `!= 3` |
| 落款日期取到别的日期 | 正序找第一个日期会命中正文残留 | 落款区间**倒序**取最后一个 |
| 文档里的多行命令被粘成一行 | 在 Python 三引号里写 `\` 续行，反斜杠把换行吃掉了 | 命令写成单行，注释另起一行 |

## 5. 留下的待办

1. **C 组 `text_start_end` 未抽取**：判决书载明的起止日目前没被用上，一律按强制措施段
   或生效日推。补上它能减少对「生效日期」录入的依赖，应优先于接真实模板。
2. **法院真实模板未验证**：占位符被 Word 拆成多个 run 的问题只能在真实模板上暴露。
   替换步骤已写进 `09` §7 与 `resources/templates/README.md`。
3. **管制折抵的羁押天数未传**：`compute_span(custody_days=...)` 支持，但「羁押天数」
   还没有录入项，管制案件届满日会偏后。
4. **界面未接数据流**：`ui/` 仍是空窗口。最低可用版本是「选文件 → 显示抽取结果与阻断
   原因 → 补录生效日期 → 生成」，直接调 `pipeline.generate()`。
5. 并发写同一归档目录无锁（单机单人可接受，多进程部署前必须加）。
