# 复核界面：从空窗口到可用

> 2026-10-31 · 对应提交「feat(ui)」

## 起点

`ui/main_window.py` 是一个空窗口加一张台账表：唯一的真实功能是读 SQLite，
「导入判决书」「生成文书」两个按钮都只弹「尚未实现」。`pipeline.generate()` 已经能跑通全链路，
但界面没调用它，所以打开程序看不出这个软件是做什么的。

## 方向：不是设计得更漂亮，而是设计得更少

读了两份规范（pbakaus/impeccable、Leonxlnx/taste-skill）后，方向被压窄了：

- impeccable 把界面分成 Persuade / Operate / Read / Experience，其中 **Operate 的「野心表现为
  精确与克制，用户已经熟悉的模式值得保留」** 直接适用。
- taste-skill 对工作界面放开低调边框、小标签、重复面板，但坚持 **"Red is a signal, not a texture"**。

所以第一版线框里那些「像个设计稿」的东西反而要删：

| 第一版 | 定稿 | 原因 |
| :--- | :--- | :--- |
| 选中行 2px 红色左边条 | 整行浅灰底 `#eeeeee` | 色条装饰是生成式界面的典型破绽；灰底是文件列表的通行做法 |
| 一行里三处红（标签 + 字段 + 整行底色） | 只有左侧一个琥珀标签 | 一个对象最多一处强调色 |
| 字号五档拉开（12/13/15/17/22） | 四档，只差 1–2px | 办公软件里夸张对比只会制造噪音 |
| 蓝色主按钮 | 近黑 `#1d1f20` | 蓝色在 Win7 Aero 下会和系统高亮色打架 |
| 技术词（阻断 / 队列 / A 组 / E-ID） | 待补充 / 待办 / 案件信息 / 缺公民身份号码 | 用户是书记员，不是工程师 |

## 实现分层

```text
ui/review.py       视图模型：字段清单、待办行、结论句、补录解析。纯函数，不 import tkinter
ui/theme.py        配色与字号；字体族按系统实有字体挑（雅黑 UI → 雅黑 → 黑体 → 宋体）
ui/widgets.py      ScrollArea / SlimScrollbar / QueuePanel / FieldTable / SourcePanel / EmptyState
ui/main_window.py  组装与事件；只调 pipeline，不判业务
```

`review.py` 不 import tkinter 是刻意的：29 项测试不需要图形环境就能锁住
「张三这一份只差公民身份号码」「原文第 5 段」这类句子，以及阻断优先排序。

## pipeline 拆成三段

界面选完文件要立刻显示字段与缺失项，但**不能落盘**；改一个生效日期要重算，但**不该重读 PDF**
（老机器上解析是秒级）。所以把 `generate` 拆开：

```text
prepare(path)                   读 + 抽，纯读
plan(document, …)               只算「能出什么、卡在哪」，不落盘
generate(prepared=document, …)  落盘 + 归档 + 台账
```

`generate(path)` 仍然可用，内部就是 `prepare → plan → 落盘`，命令行一行不改。
界面走 `prepared` 复用，与命令行的产物逐字相同（有测试钉住）。

顺带加了 `start_dates: dict[int, date]`：多被告人时起算日要能逐人给，
原来只有全局 `start_date`。

## 踩到的坑

1. **`pack_propagate` / `grid_propagate` 用错开关，左栏被撑到 460px**（设的是 252）。
   左栏内部用 pack 排布，却调了 `grid_propagate(False)`，于是宽度由卡片内容决定，
   把右侧滚动条挤出了窗口右缘 10px——截图上表现为「滚动条不存在」。
2. **滚动条画了但看不见**：Windows 的 classic `tk.Scrollbar` 忽略 `bg`/`troughcolor`，
   统一画成系统按钮面 `#f0f0f0`，与窗口边框同色；`ttk.Scrollbar` 在 vista 主题下只有 6px 且同样淡。
   两条路都看不见，最后自绘一个 `Canvas` 细滚动条（10px，#c2c6cb 圆角色块，可拖动）。
3. **已填字段全画输入框，整屏像待填表单**：改成「只有缺的才画框」，已填的悬停才变底色，
   双击才出编辑框。这一改让界面干净很多，也把「哪里真缺」凸显出来。
4. **原文面板常驻占掉三分之一高度**：22 个字段只能看到 10 个。改成默认收起、
   点字段自动展开（`SourcePanel.expand/collapse`），默认状态字段区几乎占满。
5. **截图被 DPI 裁掉右半边**：进程不设 DPI 感知时，`ImageGrab` 抓的坐标是逻辑像素，
   125% 缩放下只截到窗口左上角。截图脚本改为 `SetProcessDpiAwareness(2)` + `tk scaling = 96/72`，
   并按外框矩形抓图后左右裁掉 DWM 阴影。
6. **日期要求补零会让人重敲一遍**：`2023-5-21` 是手输的常态，`date.fromisoformat` 不认。
   改为正则拆年/月/日再构造，同时接受 `2023年5月21日`、`2023/5/21`。

## 验证

- 206 项单元测试全绿（新增 29 项界面视图模型 + 5 项 `prepare`/`plan`）。
- `ruff` 零告警，`ast.parse(feature_version=(3,8))` 全量通过。
- 四种状态逐张截图核对：空状态、已导入、有缺失、点字段后原文展开。
  截图存 `docs/images/`，工具是 `tools/ui_screenshot.py`。
- 关键断言：字段分组顺序、必填/选填/「不填有后果」三种空值显示不同、
  TXT 通道不出现「第 N 页」、阻断项排在待办最前、阻断码不出现在屏幕上。

## 没做完

1. **未在 Win7 + 1024×768 真机截图**。布局按这个尺寸设计，但字体度量与 DPI 行为需实测；
   pt→px 有 1px 级偏差，需按实际像素校字号与行高。
2. **没有台账历史列表**。已生成的文书只能在输出目录里找，二期入口应放状态栏。
3. **多被告人一次全出**。人工起算日已能逐人给，但「生成」是一次出全部文书，不能只出一份。
4. **原文不支持反向定位**（点段落跳字段），只做了字段 → 原文。
