# 2026-11-01 · 判决书载明的起止日：抽出来，但不采用

## 1. 本次目标

上一轮留下的第一顺位待办：**抽 C 组「判决书载明的刑期起止日」**。当时的事实是
系统只用「起算日 + 刑期 − 1 日」推算，判决书写在注释段里的「即自X日起至Y日止」
一个字都没读；`calc/consistency.py` 写好了、也导出在 `calc/__init__.py` 里，
但没有任何地方调用它——一段从未执行过的代码。

## 2. 做了什么

1. **抽**（`extract/defendant.py`）：`_SPAN_RE` 认「即自/即从/自/从 … 起至 … 止」，
   落进 `Defendant.text_start` / `text_end`，带段落溯源。
2. **校验**（`calc/consistency.py`）：抽取层与 `pipeline.plan` 两处都调。
   - `V1`：算得出但与载明不一致，写明四个日期与「计算值晚/早 N 天」；
   - `V2`：起算日待人工填时，比「载明区间 vs 刑期」的长度差；
   - 一致时不报任何话。
3. **报告与界面**：`DocumentItem` 增 `text_start` / `text_end` / `consistency`；
   界面「量刑与刑期」增一行「判决书载明」，只在载明时出现；并罚阻断的提示语
   带出载明日期。
4. **修锚点**：`anchors.text_before_end_marker()`——刑期注释段与「如不服本判决」
   拼成一段时，在标记处切开，主文与落款各取所需。

## 3. 为什么只校验、不采用

最省事的做法是「原文写了就用原文」。**不能这么做，理由是数据本身。**

载明值 = 起算日 + 刑期 − **羁押折抵** − **前罪已执行刑期**。后两项首部读不出来：

| 样本 | 载明 | 推算 | 差 | 原文里那句话 |
| :--- | :--- | :--- | ---: | :--- |
| （2024）冀0481刑初101号 陈某 | ～ 2024-04-10 | ～ 2024-04-15 | 5 天 | 「折抵5日」 |
| （2014）甬余刑初字第633号 颜某 | 2014-04-17 ～ | 2014-03-22 ～ | 4 天 | 「共折抵二十二日」 |
| （2014）梁刑初字第12号 张某祥 | 2013-10-16 ～ | — | 167 天 | 撤销缓刑，前罪已执行部分刑期 |

**推算不出载明值是常态，不是缺陷。** 也正因如此，反过来把载明值直接印上文书同样
危险：载明值是抄的，抄错一次就变成一份错文书，而且没有任何人会去验算。
两边都摆出来、把判断留给人，是唯一不会同时犯这两种错的做法（ADR-017）。

一个具体的收益：`V2` 报出「差 22 天」，正好对上原文那句「共折抵二十二日」。
数字看得见，承办人才知道「只是折抵，不是抽错了」。

## 4. 踩到的坑

### 4.1 最后一名被告人的注释段被划进落款区

（2024）冀0481刑初101号三名被告人的注释段连着排，段内都没有姓名，靠「续段归属于
上一个被告人」接上。但注释段以「）」结尾，清洗层不认为句子结束，**第三段的注释
与「如不服本判决」拼成了同一自然段**——锚点把整段划给落款，第三个（也是最后一个）
被告人的载明起止日就永远抽不到。

这次是两个样本同时中招（S001 史某国、S004 张某祥），而且是静默的：抽不到就是
`(None, None)`，与「判决书本来就没写」长得一模一样。

处置：`locate()` 在落款标记处判断交界段前半是否有内容，有则让 body 与 tail
都取这一段；`index_body` 也按标记截断，免得那句「如不服本判决，可在……提出上诉」
被算到某个被告名下。

### 4.2 三种同形的「自…起至…止」

S004 一份判决书里出现了五种「自…起至…止」，只有两种是本案刑期：

- 前罪刑期：`刑期自2008年6月30日起至2014年6月29日止`
- 假释考验期：`假释考验期自2013年2月4日起至2014年6月29日止`
- 缓刑考验期：`缓刑考验期自2013年3月27日起至2015年3月26日止`

按日期形状取，前罪那处会**静默覆盖**本案的。判据用主文刑期注释段的固定用语
（「判决执行之日起计算」「先行羁押」「折抵」）——前罪句与考验期句都不会写这些；
再在匹配点前 8 字内排除「考验期」兜底。

### 4.3 「相差 -4 天」

第一版 `V1` 用 `(计算止日 − 载明止日).days`，遇到载明更晚就写成「相差 -4 天」。
复核的人正在判断「该信哪一个」，不该再让他换算正负。改成「计算值晚 5 天 / 早 4 天」。

## 5. 留下的待办

1. **「折抵天数」录入项**。`compute_span(custody_days=...)` 早就支持，填进去推算值
   就能与载明值对上，`V1` 与 `W-CONTROL-OFFSET` 一起消失。这是本轮暴露出的
   最明确的一个缺口——S008 三个人的 5/3/1 天、S003 的 22 天都能靠它闭合。
2. **载明值的使用口径尚未定**。若业务方要求「有载明就用载明」，只需在 `resolve_span`
   加一处优先级，本轮的校验、溯源、告警全部复用（ADR-017 代价第 3 条已写明改法）。
3. 样本族仍缺：再审改判、死缓、未成年被告人、多个直接责任人、一句定两人（`docs/12` §6）。
4. 老阻塞项不变：真实法院模板、Win7 真机、3.8.10 交付包重建。
