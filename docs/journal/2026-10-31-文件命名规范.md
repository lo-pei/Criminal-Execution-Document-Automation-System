# 文件命名：让文件名自己说明白

> 2026-10-31 · 对应 ADR-015

## 起点

现场交来的判决书 PDF 叫「扫描件001.pdf」「微信图片_20230510103045.pdf」——案号、当事人、
日期一个都没有。这类文件进了系统，人只能靠一份份点开来找回卷宗；而输出侧的执行通知书虽然
已经是 `{案号}_{被告人}_{文书类型}_{日期}.docx`，规则却写死在 `storage/archive.py` 里，
和源文件毫无关系。同一个案子的判决书与通知书，名字格式不一样。

需求方要的是两句话：**先看内容再改名；输出的文书也要能检索。**

## 做了什么

```text
storage/naming.py     命名规则（纯函数）+ 改名方案 + 一次 rename
extract/doc_type.py   文书类型识别：标题行 → 判决如下 → 起诉语
storage/archive.py    退化成薄封装，改调 naming；不再维护第二套拼法
pipeline.py           PreparedDocument.doc_kind / name_plan() / rename_source()
cedas rename          新子命令，默认预演，--apply 才落盘，支持多文件
ui/main_window.py     状态栏显示文件名；右侧「规范文件名」入口；确认框
ui/review.py          rename_prompt：四种情形四种说法
docs/11、ADR-015、tests/test_naming.py（25 项）
```

规则只有一条，两处共用：

```text
案号_当事人_文书类型_日期[_vN].扩展名

（2023）京0105刑初123号_张三等3人_刑事判决书_20230501.pdf     ← 源文件
（2023）京0105刑初123号_张三_执行通知书_20230501_v2.docx      ← 输出
```

## 四个判断

**一、案号是取名前提，不是可选项。** 案号认不出来就**不改名**，界面直说「还改不了文件名」。
先改出一个无案号的名字、补录完再改一次，中间那段时间的名字反而误导人。
同理，人名缺了就只写 `案号_刑事判决书_日期.pdf`——缺项跳过，不写「未识别」占位符，
因为占位符会被检索当成关键词抓出来。

**二、改名必须人触发。** 这是全系统唯一会动用户已有文件的动作。命令行默认只打印
「原名 → 新名」，`--apply` 才动手；界面一定弹确认框，把两个名字并排列出来。
不搞「选中即改名」的便利。

**三、重复用哈希判，不用文件大小。** 同一天扫的两份文书页数一样、大小一样，内容不同。
用大小判重会把一次该做的改名吞掉。反过来，内容真相同的就让操作员自己决定留哪份——
同一份判决书留两份，日后分不清底稿。

**四、版本号挪到末尾。** 原先是 `..._v2_执行通知书_20230501.docx`，`v2` 夹在类型与日期之间，
同案同人的不同版本排不到一起，而「找最新一版」正是复查时最常做的事。

## 踩到的坑

| 现象 | 原因 | 处置 |
| :--- | :--- | :--- |
| 改名在「内容相同」时抛「已有同名文件」 | 起初把内容比对当成幂等判据，其实「名字已相同」那支早已覆盖幂等；它真正服务的场景是重复文件 | `NamePlan.duplicate` 单独标记，`apply_rename` 直接报「这份已经在了」，不尝试覆盖 |
| 「附带民事判决书」被判成「判决书」 | 后缀匹配按字典顺序，「判决书」先命中 | 键按长度降序排；`附带民事` 单独建类，不合并进纯刑事 |
| 标题行匹配不上 | PDF 通道把标题拆成「刑事 判决书」 | 匹配前去掉全部空白 |
| 两处测试突然失败 | 版本号位置一改，`_v2_` 的断言全部失效 | 命名是契约：改一处要同步测试与 CHANGELOG，不能只改实现 |
| 状态栏被长文件名挤歪 | 文件名 25 字以上时右侧入口被推向边缘 | 状态栏里的文件名截断到 30 字，尾巴多是时间戳，没有信息量 |
| 每帧算一次命名方案会不会读盘 | 目标不存在时不碰盘；只有撞名时才比对哈希（10MB ≈ 30ms） | 属异常路径，可接受；真正的成本在 PDF 解析，那个已经拆掉了 |

## 留下的待办

1. 界面一次只开一份判决书，批量整理目录仍要走 `cedas rename --apply 目录/*.pdf`。
   多选导入要连同「跨案批量」一起设计，不宜半做。
2. 文件被占用时的报错文案是推出来的（PermissionError → 「请先关闭」），
   需在 Windows 真机上拿一个正开着的 PDF 验一次。
3. 若已有现场装过旧版本，升级说明里要写明：**旧文件不会被自动改名**，
   且历史文件名的 `v2` 在中间。
4. 台账只记输出文书，不记源文件。这是刻意的（源文件路径不稳），
   但如果将来要做「从台账回溯到判决书」，得先有一个受控的案卷目录协议。
