# 公开语料与计算回归

## 1. 本次目标

20 份样本判决书还在等业务方提供。等待期间不该空转，于是换一个角度：
**用公开裁判文书验证 `calc` 层**——法院在判决主文里写死的刑期起止日，正好可以反算校验
我们的「起算日 + 刑期 − 1 日」。

## 2. 做了什么

- 用北大法宝 MCP 检索四批一审判决书（盗窃 / 危险驾驶 / 故意伤害 / 诈骗，基层法院，2026 年 9–10 月），
  取 40 条，剔除 3 条字段异常，落成 `data/public-corpus/cases.jsonl` 共 36 条。
- 新增 `tools/corpus_regress.py`：从主文解析「刑期 + 起止日」，调 `calc` 复算，四类判定（MATCH /
  MISMATCH / NO_DATE / UNPARSED）。
- 新增 `tests/test_corpus_regress.py`（6 项），把回归结论固化成防回退闸门。
- 修复刑期解析的日分量缺失，并同步 `SentenceSpan` / `Defendant` / 格式化 / CLI。
- 文档：`docs/08-公开语料与计算回归`、`data/public-corpus/README.md`；
  真值表新增「待确认口径」工作表（6 项）。

## 3. 为什么这样做

**合成样本不能自证。** 我按自己理解的文书样式造样本，再用它验证我自己写的规则——这是循环论证。
公开文书提供的是外部的、不随我意志变化的事实：主文里的起止日是法院写的，不是我算的。

**先验计算层，后验抽取层。** 抽取依赖大量真实文本形态，没有样本做不了；但计算只依赖
「刑期表述 + 起止日」这一句，公开文书的主文里就有。所以计算层可以提前闭环。

**只有主文也能验出真问题。** 一开始以为没首部就没价值，结果第一条就撞上
「拘役一个月十五日」被解析成一个月——这类错误会让执行通知书的届满日整体偏移半个月，
是最不该出的错。

## 4. 踩到的坑

| 现象 | 原因 | 处置 |
| :--- | :--- | :--- |
| 「拘役一个月十五日」算出的届满日比文书早 15 天 | `parse_term` 只取年月两个分量，「十五日」被整体丢弃 | 加 `days` 分量；`compute_end_date` 支持日数 |
| 先加日再加月，结果差一天 | 月日分量的运算顺序影响结果 | 固定为「先加月 → 再加日 → 减 1 日」，并用（2026）皖0881刑初147号钉死 |
| 数罪并罚案件算不吻合 | 一个句子里有多次「判处」，第一个不是最终刑期 | 优先取「决定执行」；仍不吻合的标记为法定扣减，不判为 bug |
| 法宝「裁判结果」字段有时是法条原文、有时为空 | 上游数据脏 | 剔除 3 条；在语料 README 里记下来，提醒后续任何摘要接口都要防空值错位 |
| 元典智库连不上 | 连接器已授权但本会话未暴露检索工具，网页端需登录 | 语料只有法宝一个来源，已在 08 文档记录为已知缺口 |

## 5. 留下的待办

- **语料扩到管制、单处罚金、剥夺政治权利、无期徒刑**——这四类主文形态目前只有合成测试。
- **元典智库的交叉来源校验**：同一案号在两家库里的主文是否一致，可用来发现转录错误。
- **首部形态仍无真实样本**：B 组身份字段的命中率仍未验证，只能等业务方那 20 份。
- 真值表「待确认口径」6 项需业务方先填，否则 C 组无法定稿。
- 语料含真实法院名与案号，仓库转公开前必须移除 `data/public-corpus/`。
