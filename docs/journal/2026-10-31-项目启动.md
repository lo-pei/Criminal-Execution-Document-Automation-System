## 3. 为什么这样做

### 3.1 输入通道改为双轨（ADR-005）

业务方只能提供人工从 PDF 全选复制的 TXT，生产环境仍处理 PDF。若为 TXT 单独写清洗逻辑，两条通道的行为会漂移，在 TXT 上验证的规则对 PDF 无效。

处置：两条通道都产出 `RawBlock`，共用 `cleaner.clean()`。代价是 TXT 通道丢失页码、字号、坐标，三项能力降级已写进架构文档，并把「在 ≥10 份真实 PDF 上回归通过」设为阶段 2 的退出门槛。

### 3.2 字段字典改为 A/B/C/D 四组结构

原始需求把「罪名、主刑刑种、刑期」当作标量。遇到数罪并罚（一人数罪、分别量刑后决定执行）会直接失效。改为 `crimes[]` + `merged_sentence` 两级结构，`Defendant` 同时持有 `SentenceSpan`。

### 3.3 真值表由脚本生成

手工维护的 Excel 一定会与字段字典脱节：改了字段忘了改表，或反过来。改为脚本生成，字段定义只在一处，重新生成即可。这与「规则库外置」是同一个思路——把易变的东西从易腐的载体里拿出来。

### 3.4 不引入 Qt、不打包模型

见 ADR-003、ADR-008。核心判断是：4GB 内存的旧机上，每 100MB 常驻内存都是真实的负担，而这两项都换不来必需的能力。

## 4. 踩到的坑

| 现象 | 原因 | 处置 |
|---|---|---|
| 全角数字未被转换 | `str.translate` 的键必须是码位（int），我最初用了字符 | 改为 `{code: code - 0xFEE0}` |
| 标题与正文被拼成一段 | 软换行规则把「刑事判决书」和后一段正文连起来了 | 增加「标题/落款行独占一段」的判定，宁可多切 |
| 落款日期黏在「审判长李四」后面 | 同上，落款行不以标点结尾 | 同上，并补 `_DATE_LINE_RE` 把落款日期单独分类 |
| 页眉重复行未被剔除 | 计数时用原始文本，比对时用规范化文本，两边不一致 | 计数前统一 `normalize()` |
| ruff 报 600+ 个「易混淆 Unicode」 | RUF001-003 会把中文全角标点全部判为错误 | 显式 ignore 并注明理由：中文文书系统里全角标点是正确写法 |
| `pip install -e .` 失败 | 环境缺 setuptools | 先装 setuptools 再装 |
