# 项目过程记录

按日期记录每次工作会话。**追加式，不修改历史条目。**

## 为什么单独放一个目录

交给下一个 Agent 时，文档告诉它「规则是什么」，过程记录告诉它「这些规则是怎么形成的、踩过哪些坑、哪些判断后来被推翻了」。少了后者，接手方很容易重新走一遍已经被否决的路。

## 写法

一篇一个日期，文件名 `YYYY-MM-DD-主题.md`，包含五节：

1. **本次目标**：开工时打算做什么
2. **做了什么**：具体的文件、命令、改动
3. **为什么这样做**：决策理由，特别是推翻先前方案的地方
4. **踩到的坑**：现象、原因、处置
5. **留下的待办**：下一任的起手式

不需要写流水账，只记录「下次会用到」的信息。临时路径、报错原文、搜索结果一律不记。
